迷ったときの決め方

エージェントを分ける理由は 3 つだけ

1 つ目は、親の文脈を汚したくない大量の読み込みです(探索・調査)。2 つ目は、並列で速くしたいときです。3 つ目は、権限や視点を分けたいときです(読み取り専用、批評役)。どれにも当たらないなら、エージェントを分けずにスキルで専門化します。

境界は「引き継ぎが少ない線」に引く

エージェント同士は要約でしか話せません。そのため、境界をまたぐ情報が多いと品質が落ちます。職能別(FE / BE)は、API の形を何度も往復するなら引き継ぎが重くなります。機能別やデータ分割は、境界をまたぐ情報が少なくて済みます。

スキルの粒度は「一緒に読まれるもの」で決める

スキルの説明文は常に読み込まれ、本文は呼ばれたときに読み込まれます。毎回一緒に使う知識は 1 つにまとめます。大きくなったら、本文を目次にして詳細を別ファイルに逃がします(段階的に読み込ませる)。たまにしか使わない手順は、別のスキルとして切り出します。
